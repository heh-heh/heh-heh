# 12팀 독립 경쟁 및 교차 검증 프로토콜

## 독립 실행 규칙

- 각 팀의 **Round 1**은 `PROJECT_BRIEF.md`, `EVIDENCE_REGISTER.md`, `RUBRIC.md`, 그리고 자신의 `teams/Txx.md` **만** 입력받습니다.
- 공통 토대·근거는 동일하게 하고 다른 팀의 초안, 평가점수, 숨은 지시를 주지 않습니다. 환경·모델명·프롬프트/해시를 기록합니다.
- 실제 별도 API 호출 또는 별도 에이전트 실행이 있어야 “독립 생성됨”으로 표기합니다. 같은 모델의 역할극 12개 출력을 독립 실행이라고 부르지 않습니다.
- 어떠한 팀도 코드 변경, 배포, 실거래, 학습 데이터 접근 권한을 갖지 않습니다. 평가 대상은 설계 문서입니다.

## 검토 쌍 (고정된 회전 배정)

각 팀 Tnn은 `+1`, `+5` (12팀 순환) 두 팀의 제안을 **각각** 비평합니다. 따라서 각 제안은 다른 2팀에게 비평을 받습니다.

## 요구 출력 (매 라운드)

**제안**: 요약 / 설계 선택 2개 이상 / 장단점 / 시스템·데이터 계약 / 핵심 불변식 / 실패 사례 / 실험 / 수치 예산(가정 표시) / 근거 ID / 미해결 질문.

**동료 심사**: 각 대상에 대해 의심되는 주장, 증거 수준 E0~E4, 치명도 (Critical/High/Medium/Low), 반례, 재현 가능 검증 절차, 수정 요구, 상대 초안에서 받아들일 가치 있는 강점.

**재설계**: 반박 수용/거절/보류 여부, 변경 이전/이후, 자료·실험으로 증명할 부분, 남은 이견. 비판을 받았다는 이유만으로 자기 주장 철회 강제하지 않음.

**통합**: 쟁점별 경쟁 대안의 점수와 설명, 실패 사례, 불확실성, 결정문(ADR), 남은 위험, 단계별 MVP 권고, 검증 작업 순서.

## 투표·점수와 차단 게이트

`RUBRIC.md` 기준 100점은 비교용이며 **단순 합산 상위 = 승인**이 아닙니다. 보안/미래 데이터 참조/가짜 체결/현금 생성/현실성 Critical 문제는 게이트로 차단합니다. 반례를 피해 간 모델은 점수가 높아도 탈락할 수 있습니다.

팀당 2개 리뷰가 없거나 서로 다른 reviewer가 아니면 12팀 교차 검증 “완료” 표시 금지. 충분한 실제 로그가 없는 주장 E0~E1 그대로 남깁니다.

## 추적성·출처

- `runs/` 아래 작성물/메타데이터에 `teamId`, 단계, 모델, UTC 시간, 근거 해시, 관련 리뷰어 정보를 저장합니다.
- 사용자 PC에서 생성된 파일은 **자동 push 금지**, 자동 Notion 반영 금지.
- 원문 응답은 감사용으로 보존하되, 외부 공유 전 보안/저작권/품질 검토.
- 반박과 원안의 상호 링크를 제거하지 않습니다.

## 단계 합격 선언

1. **DESIGN_READY** — 12개 독립 초안 + 24개 대상 리뷰 + 12개 수정안 + 통합 초안 존재.
2. **RESEARCH_READY** — Critical 조치, 데이터 시맨틱, 실험의 사전등록, 증거 링크까지 검수.
3. **ENGINE_READY** — 구현 및 불변식 시험 통과.
4. **MARKET_VALIDATED** — 독립 데이터·다중 시드·교란 시나리오 실측 성립.
5. **LIVE_ELIGIBLE** — 별도 인간 승인·실계좌 법률/리스크 검토가 필요하며 자동 부여하지 않음.

현재 상태는 **FRAMEWORK_CREATED**입니다.
